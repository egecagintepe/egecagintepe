## How I approach engineering

- **Start with the system, not the stack.** Understand data flow, dependencies, operators and failure modes before adding another framework.
- **Make safety and recovery explicit.** Especially when software can touch real hardware or production data.
- **Separate evidence from aspiration.** A working demo, automated tests and a validated real-world system are three different things.
- **Use AI as an engineering tool, not a credential.** AI-assisted implementation helps me move faster; reviews, tests and measured outcomes have to support the result.
